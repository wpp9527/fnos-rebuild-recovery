# Claude Code 编码最佳实践

> 源自 Andrej Karpathy 的 LLM 编码指南

## 四大核心原则

### 1. Think Before Coding（先思考再编码）

**不要默默做决定。**

```
❌ 错误：
用户：实现一个缓存
助手：（默默实现 Redis）

✅ 正确：
用户：实现一个缓存
助手：我理解您需要缓存功能。请确认：
- 内存缓存还是持久化缓存？
- 需要过期策略吗？
- 预期并发量多大？
```

**困惑时停下来：**
- 如果对需求有多个理解，停下来询问
- 不要猜测，澄清后再行动
- 明确所有假设

---

### 2. Simplicity First（简单优先）

**最少的代码解决问题。**

```
❌ 过度工程：
class CacheManager:
    def __init__(self):
        self._cache = {}
        self._lock = threading.Lock()
        self._stats = {'hits': 0, 'misses': 0}
        self._eviction_policy = 'LRU'
        # ... 200 行

✅ 简单实现：
cache = {}

def get(key):
    return cache.get(key)

def set(key, value):
    cache[key] = value
```

**重构原则：**
- 如果 200 行可以是 50 行，重写
- 先让它工作，再让它完美
- YAGNI（You Aren't Gonna Need It）

---

### 3. Surgical Changes（精准修改）

**只修改必要的部分。**

```
❌ 随意修改：
# 重构整个模块
# 添加了 5 个新类
# 改变了命名风格
# 用户只要改一个 bug

✅ 精准修改：
# 只修复了这个 bug
# 保持其他代码不变
# 匹配现有风格
```

**每个修改都应该追溯到用户请求。**

---

### 4. Goal-Driven Execution（目标驱动执行）

**定义成功标准。**

```
✅ 好的目标：
"实现用户登录功能，成功标准：
- 用户可以用邮箱/密码登录
- 登录失败有明确错误提示
- 登录状态持久化 7 天"

❌ 模糊的目标：
"做个登录功能"
```

**循环直到验证：**
1. 实现功能
2. 验证成功标准
3. 未达标则调整
4. 重复直到成功

## 常见陷阱

### 陷阱 1：假设上下文

```
❌ 用户说"修复 bug"
助手假设：知道是哪个 bug、在哪、怎么修

✅ 用户说"修复 bug"
助手询问：请提供 bug 的具体信息
```

### 陷阱 2：过度工程

```
❌ 用户要一个脚本
助手：创建了一个框架、配置系统、插件架构...

✅ 用户要一个脚本
助手：写了一个 20 行的脚本
```

### 陷阱 3：忽略反馈

```
❌ 用户：这不是我要的
助手：继续按原方向推进

✅ 用户：这不是我要的
助手：停下来，重新理解需求
```

## 最佳实践

### 代码风格

1. **一致性**：匹配现有代码风格
2. **可读性**：代码是给人看的
3. **简洁性**：删除不必要的代码

### 提交习惯

1. **小步提交**：每个修改一个 commit
2. **清晰消息**：说明为什么改
3. **可回滚**：保持每个提交独立

### 调试技巧

1. **先复现**：确保能重现 bug
2. **二分法**：缩小问题范围
3. **验证假设**：打印、日志、断言

## 使用建议

### 对太子

- 分拣任务时，先明确优先级
- 不要默默决定任务分配
- 简单任务简单处理

### 对中书省

- 规划方案时，先确认需求
- 最小可行方案优先
- 避免过度设计

### 对门下省

- 审查时检查是否遵循四大原则
- 识别过度工程
- 确保修改精准

### 对兵部/工部

- 编码前先思考
- 保持代码简单
- 每个修改追溯到需求
