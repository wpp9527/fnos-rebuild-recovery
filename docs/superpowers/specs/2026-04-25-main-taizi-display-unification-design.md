# 2026-04-25 main==taizi 展示语义收口设计

## 背景

已确认统一口径：

- OpenClaw 运行时默认入口仍为 `main`
- 治理展示语义统一为 `taizi / 太子`
- 所有任务从 `main` 进入，但对用户可见的 UI / dashboard / 文案层优先显示“太子”
- 兼容策略采用中等强度收口：**展示层 + 前端语义层统一**，但不硬改底层运行时 ID 与状态机基础键名

## 目标

本轮实现以下目标：

1. 用户可见展示中不再出现 `主控` 作为 `main` 的展示名
2. 用户可见展示中，`main` 一律映射解释为 `太子`
3. dashboard / 前端提示 / 前端映射层对 `main` 与 `taizi` 的显示语义保持一致
4. 保留底层运行时 `main` 以及必要的兼容映射，不做历史数据迁移

## 范围

### 本轮纳入

- `dashboard/dashboard.html`
- `dashboard/server.py`
- `edict/frontend/src/store.ts`
- 必要时补充少量测试，覆盖 `main -> 太子` 的展示映射

### 本轮不纳入

- OpenClaw runtime 底层 agent id 改名
- 任务状态机键名大重构（如 `Taizi` → 其他）
- 历史任务数据迁移
- `dist/*` 全量重建
- 大范围无关文案整理

## 设计方案

### 方案选择

采用“展示层 + 前端语义层统一”的方案：

- 底层保持：`main` 仍是 runtime id
- 展示层统一：用户看到的一律优先是“太子”
- 前端映射统一：凡是展示 label map / badge map / message 文案，`main` 与 `taizi` 的显示结果一致

### 具体策略

#### 1. Dashboard 展示映射

把 dashboard 中针对 agent 的展示映射从：

- `main: 主控`

改为：

- `main: 太子`

原则：

- `main` 只作为内部兼容 id 存在
- 任何 badge / progress / log / flow 中，只要要展示名字，就显示“太子”

#### 2. 前端共享映射

检查前端共享 store / config 中所有面向展示的 label 与状态标签：

- `Taizi` 状态标签继续存在，作为兼容状态键
- 但其展示文案必须统一解释为“太子”相关语义
- 不允许出现“主控”一词作为 `main` 的 UI 展示名

#### 3. API / 服务端提示文案

服务端返回给前端或 dashboard 的提示信息中：

- 若语义指向默认入口治理角色，则统一写“太子”
- 不向用户暴露 `main` 作为角色展示名

#### 4. 兼容边界

保留以下兼容点：

- 运行时 ID：`main`
- 必要映射：`main -> taizi`
- 状态键：`Taizi`

不做：

- 状态枚举破坏式改名
- 旧数据批量修复

## 风险与控制

### 风险

1. 误把运行时兼容逻辑也改掉，导致调度异常
2. 误改 `dist` 或无关文件，扩大改动面
3. 改动状态键导致历史任务展示错乱

### 控制措施

1. 仅收口展示层映射，不改 runtime id
2. 优先精确编辑目标位置
3. 不碰 `dist`、不做状态机重命名

## 完成标准

满足以下条件即视为本轮完成：

1. 目标展示文件中，`main` 的用户可见展示名已统一为“太子”
2. `主控` 不再作为 `main` 的展示名出现在本轮目标文件中
3. 保留底层兼容逻辑，不破坏 runtime `main`
4. 给出实际检索/测试证据，而不是口头声明
