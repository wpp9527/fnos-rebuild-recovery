## 飞书渠道修复

### 问题
飞书 observer 的 `ask_openclaw` 函数 fallback 到 CPA 外网代理 (`cpi.19930901.xyz:1234`)，但 CPA 配置中没有 `openclaw` 模型，导致 502 错误。

### 根因
1. `load_model_proxy_defaults()` 从 `openclaw.json` 读 CPA 配置
2. CPA 配置的 `models` 列表中没有 `openclaw` 模型（只有 deepseek-ai/deepseek-v4-pro 和 minimax/minimax-m2.5:free）
3. CPA 的 baseUrl 是外网代理 `https://cpi.19930901.xyz:1234/v1`，不是本地 Gateway
4. Gateway 的 `openclaw` 模型是正常的（通过 `http://127.0.0.1:18789` 可用）

### 修复方案
修改 `observer.py` 的 `load_model_proxy_defaults()` 函数：
- 始终返回本地 Gateway 地址 `http://127.0.0.1:18789`
- 使用 Gateway 的 `openclaw` 模型别名
- 不再依赖 CPA 外网代理配置

### 验证
- 飞书 WebSocket 连接正常（ping/pong 成功）
- 测试消息发送成功（Status: 200, Code: 0）
- Gateway 的 `openclaw` 模型可用（回复 "pong"）
