## 3. 工程控制论框架（钱学森）

### 核心原则
1. **目标牵引** - 每个任务先明确目标，目标必须能被验证
2. **反馈闭环** - 重要动作后必须检查结果
3. **分层执行** - 目标层 → 策略层 → 执行层 → 反馈层 → 记忆层
4. **稳定优先** - 工程系统第一目标是不失控
5. **失败可见** - 失败要说明失败层级
6. **恢复可练** - 备份和自动化的价值在"能恢复"

### 闭环模板
1. 执行
2. 观测
3. 比较目标
4. 纠偏
5. 再验证
6. 记录经验

### 代理执行口令
处理任何复杂任务前自检：
1. 目标是什么？
2. 成功如何验证？
3. 反馈信号在哪里？
4. 失败会停在哪一层？
5. 是否有回滚或恢复路径？
6. 是否需要写入长期记忆/文档？

## 5. 应用到当前系统

### OpenClaw 角色
- 主控入口：调度、记忆、验证、汇报
- 不应只做 command runner
- 应负责判断、验证、复盘和沉淀

### Hermes 角色
- 另一个代理执行层
- 也应学习闭环任务范式

### 任务执行标准
- 执行结果 + 业务验证 + 异常边界说明
- 不能用"脚本退出码 0"掩盖业务失败
- 对重复失败要记录模式，形成长期规则

### 机器人项目文件规范
- 路径：`/vol1/1000/机器人/{项目名}/`
- 分析后保存必须按项目来，不要混在一起
- 文件命名：`{序号}_{功能名}.txt`（代码）
- 文档命名：`{序号}_{文档类型}.md`
- 编号规则：代码和文档使用不同编号段（如代码00-20，文档用其他编号）
